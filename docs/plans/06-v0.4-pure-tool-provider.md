# Plan 06 (v0.4.0): pure tool-provider on ADT 3.60

**Status**: implemented
**Releases**: v0.4.0
**Goal**: Make the plugin a first-class citizen of SAP's now-supported MCP
server (ADT 3.60) by dropping the reflective kickstart and relying on SAP's
activation. Plugin = tool contributions + optional autologin, nothing else.

## What changed in ADT 3.60 (the trigger)

Decompiled from `~/.p2/pool/plugins/com.sap.adt.mcp.core_3.60.0.jar` and the new
`com.sap.adt.mcp.core.ui_3.60.0.jar`:

| Area | 3.58 | 3.60 | Impact on us |
|---|---|---|---|
| Activation | none (dormant) | preference page + `AdtMcpUIStartupHandler` + `-DadtMcpServerPrefEnabled=true` | SAP now starts the server; our kickstart is obsolete |
| `startMCPServer` | `(int, String)` | `(int, String, FileSystemMode)` | old reflective call throws `NoSuchMethodException` |
| `com.sap.adt.mcp.core` export | `x-internal:=true` | `x-friends:="atc.ui, abapunit, …"` | we're not a friend; not runtime-enforced by default, but a signal |
| extension point `adtMcpTools` | — | byte-identical `plugin.xml` | tools register unchanged |
| `IAdtMCPTool.execute(String)` | abstract | `default` (+ new `execute(String, IProgressMonitor)` default that delegates to it) | our tools work unchanged |
| tool-name regex | `^[A-Za-z0-9_-]+$` | identical | unchanged |
| default port | (our 54322) | SAP default `2234` | docs/clients use 2234 |

`ADTMCPServer.start(port, token, mode)` is idempotent on the same port, but
**stops and re-binds** if asked to start on a different port than the one already
running — a good reason to *not* start it ourselves and risk clobbering SAP.

## Decision

See `docs/decisions.md` **D9** (supersedes D3). Chosen approach: **pure
tool-provider**. No reflection into SAP internals at all.

## Setup model (new)

1. Drop `com.arc1.mcp_0.4.0.jar` into `dropins/`.
2. `eclipse.ini`: add `-DadtMcpServerPrefEnabled=true` (auto-start on boot).
3. Restart with `-clean`.
4. *Preferences → ABAP Development → MCP Server* → Enable + Generate token +
   (port, default 2234) → Apply.
5. Point the AI client at `http://localhost:2234/mcp` with the bearer token.

## Verification

  the newest, i.e. 3.60.0). ✅
- Source grep confirms no remaining references to `startMCPServer` /
  `peekRunningPort` / `httpServer` / token-file. ✅

  ```bash

  export ARC1_MCP_TOKEN=<token from preference page>
  ./scripts/smoke-test.sh <destination-id>
  ```

## Out of scope (unchanged from before)

- Mutating tools that overlap SAP built-ins.
- Anything non-Eclipse / centrally-managed → ARC-1.
- Backporting 0.4.x to ADT 3.58/3.59 (use 0.3.x there).
